# 实时语音 Agent 演示 · Realtime Voice Agent

> AI 产品经理作品集项目（方向③）—— 验证"实时语音 / 音视频交互"作为产品能力的可行性。
> 对应实习岗位关键词：**实时音视频交互、语音大模型、多模态 Agent、Function Calling / MCP、RAG、模型评测**（岗位 11 等）。
> 源码：https://github.com/jian935/realtime-voice-agent ｜ 简历素材与链接见 [`简历素材-项目链接与要点.md`](简历素材-项目链接与要点.md)

## 一、这是什么（产品定义）

一个**用语音直接对话的 AI Agent** 网页 Demo。用户点一下麦克风就能开口，Agent 实时聆听、理解、语音回复，并同步显示文字字幕与"首包延迟"等指标。内置三个场景：**模拟面试官 / 外语陪练 / 自由对话**。

它不是又一个"套壳聊天框"，而是把 **Voice Agent 的完整交互闭环**（采集 → 识别 → 理解 → 生成 → 语音合成 → 播放 → 可观测）做出来给人直接体验，并进一步叠加了 **工具调用（Function Calling）** 与 **RAG 知识库** 两项硬核能力，证明对 Agent 工程边界的理解。

## 二、用户与痛点

- **谁用**：准备面试的学生、练口语的学习者、想体验语音 AI 的普通用户。
- **痛点**：现有文字 chatbot 在"口语练习 / 模拟面试"场景里割裂——你打字、它打字，没有真实对话的临场感；而真正的语音 Agent 门槛高（实时音频、双向流式、延迟敏感），多数人只停留在概念。
- **价值假设**：若语音交互延迟足够低、回复足够自然，**对话临场感**会显著提升练习 / 陪伴类场景的留存与效果。

## 三、我的产品判断（作为 PM 的关键决策）

1. **为什么做"语音"而不是再加一个文字 Agent？**
   15 个目标岗位里只有 1 个明确招"实时音视频/语音大模型"方向，但它是 2026 年明显上升的赛道，且**极少候选人能做**——差异化 > 拥挤的"通用 Agent"。
2. **为什么做"四模式"（模拟 / 国内大模型 / OpenAI 实时 / MiniMax 真时）？**
   真时模型要密钥、要网络、要麦克风，面试官/同学 Demo 时不一定具备。模拟模式用浏览器内置能力**零成本复现完整 UX**；国内大模型模式让大陆网络下也能直连真实模型（无需代理）；OpenAI 实时与 MiniMax 真时则提供真·双向流式体验。这本身也是一次产品取舍：*可演示性优先于技术纯度*。
3. **为什么场景化而不是通用助手？**
   通用语音助手已被巨头占据，垂直场景（面试 / 口语）更容易讲清"用户是谁、痛点是什么、指标怎么定义"，也更符合实习岗位要的"能定义问题、讲清贡献"的叙事。
4. **为什么加工具调用 / RAG？**
   这批 JD 高频出现 Function Calling / MCP / RAG。我把这两项做成**可见、可演示**的能力：界面实时展示"Agent 调了哪个工具、传了什么参数、返回什么"，以及"基于你上传的资料作答"，直接证明对 Agent 编排与检索增强的理解，而非只会调一个 chat 接口。

## 四、技术取舍（展示技术 Sense）

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 语音能力来源 | 识别/合成走浏览器端；LLM 走国内 OpenAI 兼容端点（DeepSeek 等）或 OpenAI/MiniMax Realtime | 大陆直连无需代理；密钥留服务端代理，不进浏览器 |
| 密钥安全 | ephemeral token 由后端签发，密钥永不进浏览器 | 标准做法，避免前端泄露 API key |
| 工具调用 | 服务端定义工具（计算器/时间/天气/搜索），DeepSeek Function Calling 循环执行 | 浏览器仅看到"调了什么"，工具逻辑与密钥都在服务端 |
| RAG | 服务端本地 TF-IDF 检索（无外部向量库），注入上下文 | 离线检索零成本，演示"基于资料作答"而无需接向量数据库 |
| 音频采样 | 24kHz 单声道 PCM | Realtime API 要求，AudioContext 自动重采样 |
| 防回声 | 麦克风经零增益节点驱动处理，不回放自己 | 避免用户听到自己的声音 |
| 可观测 | 首包延迟 + 对话时长实时显示 | 把"延迟"这个语音 Agent 核心指标显性化 |

> 切换国内大模型厂商（豆包 / 智谱 / 通义）：改 `DOMESTIC_LLM_*` 环境变量即可，前端无需改动。接入新厂商的真时双向语音：在 `server.js` 增加 token 端点、在 `app.js` 增加对应 WebSocket 适配器（参考 `startMiniMax`）。

## 五、如何运行

> ⚠️ **必须用本地服务器打开，不要直接双击 HTML 文件！**
> 直接双击会以 `file://` 协议打开，所有 `/api/*` 请求（配置、模型对话）都会拿不到响应，页面表现为"请求失败: Failed to fetch"。
> 正确做法：在本项目目录运行 `npm start`（**或双击 `start.bat`**），然后用浏览器访问 **http://localhost:3000**（首页为产品介绍，点"打开实时演示"进入 Demo）。

```bash
cd realtime-voice-agent

# 1) 模拟模式（推荐先跑，完全不需要密钥）
npm start
# 打开 http://localhost:3000 → 「打开实时演示」→ 选「模拟模式」→ 点麦克风说话（或直接用下方文字输入）

# 2) 国内大模型模式（无需代理，默认走 DeepSeek）
export DOMESTIC_LLM_KEY=sk-你的密钥
npm start
# 选「国内大模型」→ 说话或文字输入；点「⚙ 设置」可开启工具调用 / 知识库(RAG)

# 3) OpenAI 实时双向模式（需代理 + 密钥）
export OPENAI_API_KEY=sk-...
npm start

# 4) MiniMax 真时双向模式（国内，无需代理，需密钥 + 组 ID）
export MINIMAX_GROUP_ID=你的组ID
export MINIMAX_API_KEY=你的密钥
npm start
```

### 切换国内大模型厂商
默认对接 **DeepSeek**（`api.deepseek.com`，OpenAI 兼容）。**在页面上即可切换**：打开演示页 →「⚙ 设置」→「国内大模型服务商」下拉，选 DeepSeek / 智谱 GLM / 通义千问 / 豆包（火山方舟）/ 自定义。切换后到模式栏点「国内大模型」重填该服务商的 Key 即可（Base URL 与模型名由服务端预设决定；豆包填接入点 ID `ep-...`；「自定义」可自填 Base URL 与模型名）。

如果你想用环境变量固定某个厂商（例如部署时），也可在启动前设置，前端同样无需改动：

```bash
# 例：通义千问（阿里云百炼，OpenAI 兼容模式）
export DOMESTIC_LLM_KEY=sk-...
export DOMESTIC_LLM_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
export DOMESTIC_LLM_MODEL=qwen-plus

# 例：智谱 GLM
export DOMESTIC_LLM_KEY=...
export DOMESTIC_LLM_BASE=https://open.bigmodel.cn/api/paas/v4
export DOMESTIC_LLM_MODEL=glm-4-flash
```

> 浏览器 `getUserMedia`（麦克风）需安全上下文（localhost 或 https）。国内 Chrome 的**语音识别**（Web Speech）后端是 Google，在大陆可能连不上——此时直接用页面下方的**文字输入**即可正常对话，语音播报（TTS）由浏览器本地完成、不受影响。

### 模式旁边的 🔓「需密钥」是什么意思？可以直接填吗？
演示页顶部「模式」里，**国内大模型 / OpenAI 实时 / MiniMax 真时** 三个按钮若显示 🔓「需密钥」且未置灰，说明对应的密钥还没配置——但它们**可以点**：点一下就会弹出一个密钥输入框，直接把 Key 填进去即可使用（无需改环境变量、无需重启服务）。

- **国内大模型**：填 DeepSeek API Key（默认走 DeepSeek），填完即生效，只发往本站服务端做代理（不保存到磁盘），不会直连暴露给第三方。
- **OpenAI 实时 / MiniMax 真时**：分别填 OpenAI Key、或 MiniMax 的 Group ID + API Key。

填好的密钥**只保存在本浏览器会话（sessionStorage）**，关闭标签页即清除；刷新页面需重新填。如果想长期免填，仍可用上方的环境变量方式（`DOMESTIC_LLM_KEY` / `OPENAI_API_KEY` / `MINIMAX_GROUP_ID`+`MINIMAX_API_KEY`）在启动服务前设好，那样按钮上就不会再出现 🔓。

> 安全说明：无论哪种方式，Key 都只在**服务端**被用来调用厂商接口；通过页面填入的 Key 也只发往本站服务端（本地运行时即 `http://localhost:3000`，线上版本即该托管域名），不落盘、不会直接发送给第三方。OpenAI/MiniMax 真时还走"服务端签发临时令牌"机制，浏览器全程不持有可用于直连的长期凭证。

### 改了代码刷新后页面没变化？
本项目启用了 PWA 离线缓存（Service Worker），且浏览器会缓存静态文件。若修改 `app.js` / `demo.html` / `styles.css` 后刷新看不到更新，请**硬刷新**（Windows：`Ctrl + Shift + R`；Mac：`Cmd + Shift + R`）。服务端已对静态文件下发 `no-cache`，且仅在 SW 检测到新版本时才会更新缓存（`public/sw.js` 的 `CACHE` 版本号每次破坏性改动都会递增，例如 `va-cache-v2`），因此硬刷新一次即可拿到最新内容。若仍异常，可在浏览器 DevTools → Application → Service Workers 点「Unregister」后重试。

### 国内大模型一直回复「(无返回)」或空气泡？
- **空气泡**：早前版本删除「思考中…」时只删了内层文字、没删消息框，已修复（改为整条移除）。硬刷新即可。
- **「(无返回)」**：已修复一个会导致内容全丢的解码 bug——Node `fetch` 的流式 `chunk` 是 `Uint8Array`，用 `chunk.toString()` 会得到十进制字节串而非文本，现已改用 `TextDecoder` 正确解码。若修复后仍为空，多半是 **DeepSeek 账户余额不足 / 模型名不匹配**（默认 `deepseek-chat`），请到 deepseek.com 控制台核对余额与模型名；上游若以 HTTP 200 返回 JSON 错误，服务端现在会将其透出为明确报错，而不是空回复。

## 六、四种模式的取舍（产品视角）

| 模式 | 延迟 | 是否需要代理 | 是否需要密钥 | 说明 |
|------|------|--------------|--------------|------|
| 模拟模式 | 模拟 | 否 | 否 | 零成本复现完整 UX，任何环境都能演示 |
| 国内大模型 | 中（轮次） | 否 | 国内 LLM 密钥 | 大陆直连，ASR/TTS 在端侧，支持工具调用 / RAG |
| OpenAI 实时 | 低（双向流式） | 是 | OpenAI 密钥 | 真·实时语音，体验最佳但需代理 |
| MiniMax 真时 | 低（双向流式） | 否 | MiniMax 密钥 + 组 ID | 国内真·实时语音，无需代理（以官方文档字段为准） |

## 七、能力亮点（写给技术面试官看）

- **工具调用可视化**：Agent 能调用计算器 / 时间 / 天气 / 搜索，界面实时展示"它调了什么"，体现对 Function Calling / MCP 的理解。
- **RAG 知识库**：粘贴一段资料，Agent 基于它回答（本地 TF-IDF 检索，无需外部向量库）。
- **真时双向语音**：国内 MiniMax Realtime 适配，无需翻墙即可真·实时语音（需密钥）。
- **多智能体协作**：开启后模型模拟"面试小组 / 专家团"多角色轮流发言，前端按角色着色区分（命中 JD 的"多智能体编排"）。
- **双语字幕**：外语陪练场景下，AI 英文回复自动对照显示中文译文。**模拟模式零密钥即用**（内置中英对照文案）；国内大模型模式走 LLM 实时翻译（需密钥）。体现"多模态 / 国际化"产品意识。
- **评测看板**：实时统计对话轮次、首包延迟均值、估算 Token 与成本，并可一键导出评测报告 / 对话转录（命中 JD 的"模型评测 / 数据监控"）。
- **音色画廊**：用**官方中文音色名 + 性别 + 风格**呈现（如「晓晓 ♀ 女声·多风格通用」「云扬 ♂ 男声·新闻播报」「云希 ♂ 男声·阳光活力」），一眼看懂；默认「仅显示中文」过滤掉几十个外语音色，选中音色持久化记忆。体现对"语音产品体验细节"的打磨。
- **打断（barge-in）**：实时模式下可随时打断 AI 说话，更贴近真实对话。
- **明暗主题 + PWA**：支持暗色模式与"安装到桌面 / 离线可用"，产品完成度高。
- **密钥安全**：所有模型密钥只在服务端用于调用厂商接口，浏览器从不把它直接发给第三方；在页面填入的密钥仅存于本会话的 sessionStorage（关闭标签页即清除），也可改由环境变量持久化。OpenAI/MiniMax 真时还走"服务端签发临时令牌"，浏览器全程不持有可用于直连的长期凭证。
- **可观测**：实时显示首包延迟与对话时长。
